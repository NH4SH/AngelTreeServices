## Concrete interface

All entry points are in `candidate-source/supervised-dev-recovery-adapters.mjs`. The existing context module re-exports the supervised entry points without opening its installed HOME observers, mount stub, profile cache or readiness reader.

1. `openSupervisedDevRecoveryApproval({approvalPath, approvalSha256})` reads bounded immutable detached JSON through a no-symlink, regular-file reader. The expected raw-byte digest is an explicit caller input, outside source/config/archive claims. It returns a private in-process capability. A naked approval object, copied capability, mutable file, changed path or changed approval bytes fails.
2. `createSupervisedDevRecoveryIO(capability)` is the concrete DEV transport for an **already running** Root-owned target. It requires Linux ARM64, UID501 and `lima-ats-firewood-qa`. It uses only fixed Docker inspect/info/ps and the fixed psql read-only transaction, over the local rootless socket. It checks the exact target/container/image/volume/purpose, no network/ports, read-only root, `postgres` container user and restart policy `no`. It never starts or stops a target. Root remains the actual target operator.
3. `collectSupervisedDevRecoveryEvidence(capability, io)` reads host identity and exact disk bytes before and after the transaction. It checks actual SID, database OID, database marker UUID, host boot UUID, database boot and actual OID10 bootstrap role. The transaction is repeatable-read/read-only with `search_path=pg_catalog`, UTC, `jit=off`, unchanged5-second statement and1-second lock bounds, and a12-second outer limit for the two statements together. It returns only qualified, closed DEV evidence. Fake fixtures implement the same two-method IO interface; they cannot enter the production profile cache.
4. `observeAdapterSourceClosure()` reads all59 actual transitive source/resource files. `disk.adapterSourceClosureSha256` must come from detached independent review and match this observation. The component and document digests separately hash the exact approved file metadata and bytes. No component, config or archive supplies its own expected digest. No approval file can be part of the component it approves.
5. `observeExactRecoveryDisk(capability)` checks bounded explicit component, document and optional private configuration paths, bytes, sizes, owner, mode, regular/no-link identity and stable metadata. No broad filesystem scan or private value is returned. A full runtime private configuration set is not asserted by a data-free QA run.
6. `reviewedSupervisedDevAdmissionMount(capability, mountOrCompose)` accepts only an externally reviewed exact read-only `/admission` bind for the two named new services. Compose validation requires exact nine service keys, new UID1000, restart `no`, no ports and exactly one approved admission mount for each new service. Extra admission/shared mounts fail. This is a separate validator; it does not make the existing HOME runtime blueprint path operational or restore an old permit.
7. `validateSupervisedRecoveryReceipt(capability, inputs)` hashes **raw** binding, source approval and independent registered-source-readback bytes against detached expected digests. It checks the public key's DER fingerprint and calls the preserved real `validateNativeWalReceipt` signature verifier. It requires the exact overlay,102 lineage, new namespace, generation greater than3, target boot/SID, nine distinct container identities, safe wall/monotonic clock, both280-second age checks, a SQL lease no longer than14 seconds and no later than the signed capture deadline, and exact signed paired-file and WAL component identities. It returns closed DEV validation evidence with no roles or services to enable. It contains no signer or boolean substitute for NativeProof.

The opaque observer's five digests and every count must exactly equal detached reviewed values. Unsupported/duplicate/invalid guard counts remain zero, OID10 count is one, and guards are600. The named protected200/captured201 inventories must be exact approved names: original175/176 plus the explicit25 additions, including the unchanged migration-ledger name. Counts cannot approve a same-count replacement.

The live state must remain epoch0, unheld by any writer, topology unverified, capture held, lease expired and bound to the current database boot. All nonoperator logins and sessions are closed. Handoff source and Website identity rows must be absent, Website control must have exactly one paused row, and the worker heartbeat must be the exact inert sentinel. A saved active control, source row or old restored lease is rejected. Every producer mode, role-renewal list and service-start list in the returned DEV evidence stays closed.

## Detached input requirements

`INPUT_CONTRACT_UNBOUND.json` is a schema guide, not approval. It intentionally contains no usable target or expected semantic/component/registration pins. No actual immutable approval was generated by this author. Root supplies independently reviewed data and pins the approval's raw bytes outside this code:

- Fresh actual target SID, database OID, database boot, host boot UUID, container/image/volume and marker UUID.
- The complete final **v2 continuous observer** result for that exact target. The installation recipe's reviewed `2a5207…` semantic digest uses a different recipe and cannot be copied into this field. Likewise, the earlier0.58-second grammar/equivalence result is not the finished postimage approval.
- Exact approved200/201 inventories, complete current source closure, fixed release component/DOC file sets, and any explicit private configuration/version and public-mount recipes.
- Separate raw expected binding, source approval, authority-definition/public-key fingerprints and independent registered-source readback hashes. The normalized `ats-independent-registered-source-readback-v2` record is a local explicit input contract, **not a claimed existing authority RPC or registration**. Root must obtain those bytes through its independent trusted boundary; a producer repeating them is insufficient.
- Approved source-capture/inventory and QA postimage review references. The QA collector explicitly observes the projected `08f17da6104684ddd835735c7256ab16` ledger and retains original `630f8894ce3a5c50a947b8872ed8edf3` only as provenance. It never relabels the QA ledger as observed production bytes.

An acyclic order is: review public source/component/DOC manifests; create an external policy/overlay; obtain independent source approval/registration; pin detached approval bytes outside the component; only then observe actual bytes. A new adapter-source byte forces a new external closure review. `observeAdapterSourceClosure()` is an observation, not independent approval.
