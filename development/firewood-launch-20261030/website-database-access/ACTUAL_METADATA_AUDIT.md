# Actual catalog follow-up

Independent local examination of the saved read-only `ACL-MATRIX_METADATA_READBACK.json`: 30 actual roles, 22 membership rows, 27 default-ACL entries. This differs from the deliberately smaller native permission fixture, which had 25 preexisting roles. No live catalog or application rows were changed.

The narrow rehome matches the actual matrix. All 30 existing roles currently have net USAGE, database TEMPORARY, and CONNECT. Only `supabase_admin` is a superuser. The future operator should therefore preserve net USAGE and TEMPORARY for the exact 29 existing non-super roles, revoke only those two PUBLIC privileges, leave CONNECT and every membership unchanged, and confirm the full old effective matrix is identical. The three native roles do not exist in the readback and must be created after the snapshot/rehome. The JSON companion lists the exact 29 names and all 22 membership rows. A changed live role set must trigger review rather than silently using a stale allowlist.

None of the 27 default ACL entries is a global or `app_private` override for either actual creator, `postgres` or `supabase_admin`. Defaults scoped to `public`, `storage`, or other schemas do not apply to `app_private`. Consequently, newly created private Website tables have no default PUBLIC table grant; newly created functions retain PostgreSQL's default PUBLIC EXECUTE unless explicitly revoked. The proposed wrapper correctly revokes PUBLIC EXECUTE on its immutable-trigger functions and new native/health helpers. Operator-created helpers remain owned by `supabase_admin`; Website store tables/functions created as `postgres` remain under that owner. Do not rely on inherited role membership to choose default ACLs: the actual object creator determines them.

The indirect metadata finds two net references: `extensions.grant_pg_net_access` and `supabase_functions.http_request`. Neither is reachable using both PUBLIC schema USAGE and PUBLIC EXECUTE. The former is an invoker function with PUBLIC EXECUTE but inaccessible extension schema; the latter is SECURITY DEFINER with neither PUBLIC EXECUTE nor PUBLIC schema USAGE. Native roles receive only private Website schema USAGE and no preexisting membership. This resolves the specific indirect references shown by the metadata; it does not prove the absence of every dynamically constructed SQL path.

The remaining live installation proof must still expand actual table/column/function ACLs after creating the new objects, verify exact owners and policies, and show zero new native memberships/net/TEMP/CRM/Auth/Storage access. The current saved matrix is a preimage, not evidence of the eventual 175-table-plus-new-tables postimage or recovery enrollment.
